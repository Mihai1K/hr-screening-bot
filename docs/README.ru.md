# HR-бот: менеджер по продажам

Telegram-бот для первичного сбора кандидатов. Кандидат за 2 минуты оставляет
контакты и записывается на 10-минутный созвон — HR получает карточку с кнопками
«Пригласить / В резерв / Отказ» и строку в Google Таблице.

## Воронка

```
/start
  → логотип + приветствие, кнопка «Начать»
  → описание вакансии
  → согласие на обработку данных
  → имя и фамилия
  → телефон (кнопкой Telegram)
  → ник в Telegram
  → ссылка на резюме/портфолио      (можно пропустить)
  → коротко о себе                  (можно пропустить)
  → день созвона
  → время созвона
  → подтверждение кандидату
     + карточка в HR-чат
     + строка в Google Таблице
```

Состояние анкеты хранится в базе, а не в памяти: если бот перезапустится,
кандидат продолжит с того же шага.

## Расписание созвонов

По умолчанию — 10-минутные слоты в окнах:

| День | Окно | Слотов |
|---|---|---|
| Пн | 11:00–12:00 | 6 |
| Вт | 12:00–13:00 | 6 |
| Ср | 13:00–14:00 | 6 |
| Чт | 14:00–15:00 | 6 |
| Пт | 15:00–16:00 | 6 |

Запись открыта на 10 рабочих дней вперёд — это **60 слотов**, то есть примерно
две недели. Меняется в `.env` через `CALL_WINDOWS`, `SLOT_MINUTES` и
`CALL_DAYS_AHEAD`.

**Один слот — один кандидат.** Занятые времена не показываются, а гонку двух
одновременных нажатий ловит уникальный индекс в базе (`candidates_slot_uniq`),
а не проверка в коде — двойной записи не будет физически.

Слоты на сегодня скрываются, если до них осталось меньше `MIN_LEAD_MINUTES`
(по умолчанию 90 минут).

## Запуск

Обычно бот работает сам под launchd — см. следующий раздел. Вручную:

```bash
docker compose up -d && npm install && npm start
```

Первый запуск сам создаёт таблицы и досоздаёт недостающие колонки.

## Автозапуск (launchd)

Бот зарегистрирован как служба `com.mediacentr.hrbot`: поднимается при входе в
систему и перезапускается при любом падении.

| Что | Где |
|---|---|
| Описание службы | `~/Library/LaunchAgents/com.mediacentr.hrbot.plist` |
| Пусковой скрипт | `~/hr-bot-run.sh` |
| Симлинк на проект | `~/hr-bot` |
| Лог | `logs/bot.log` в проекте |

Две неочевидности, из-за которых всё сделано именно так:

- **launchd не может запустить скрипт, лежащий в `~/Desktop`** — macOS не даёт
  ему открыть файл оттуда. Поэтому `hr-bot-run.sh` живёт в домашней папке.
  Читать и выполнять содержимое проекта на Desktop при этом можно.
- **launchd не переваривает кириллицу в пути.** Отсюда ASCII-симлинк `~/hr-bot`.

Команды:

```bash
tail -f ~/hr-bot/logs/bot.log
```

```bash
launchctl kickstart -k gui/$(id -u)/com.mediacentr.hrbot
```

```bash
launchctl bootout gui/$(id -u)/com.mediacentr.hrbot
```

Первая — смотреть лог, вторая — перезапустить (нужна после правки кода или
`.env`), третья — выключить службу совсем.

### Сторож

В боте есть watchdog: раз в 30 секунд он проверяет `bot.isRunning()`, и если
опрос Telegram встал — процесс выходит с ошибкой, а launchd поднимает его
заново. Это защита от конкретной аварии: однажды опрос умер молча, процесс
продолжал жить, и бот несколько часов не отвечал кандидатам, ничего не написав
в лог.

### Чего launchd не решает

Служба спасает от падений процесса, но **не** от закрытой крышки, сна и
отсутствия интернета. Пока бот живёт на ноутбуке, он лежит вместе с ноутбуком.
Для постоянного потока кандидатов его нужно перенести на сервер — тем более что
локализация персональных данных всё равно требует хостинга в РФ.

## Настройка (`.env`)

| Переменная | Что это |
|---|---|
| `BOT_TOKEN` | токен от [@BotFather](https://t.me/BotFather) |
| `HR_CHAT_ID` | можно не заполнять — см. ниже |
| `DATABASE_URL` | строка подключения к Postgres |
| `TIMEZONE` | часовой пояс созвонов |
| `CALL_WINDOWS` | окна по дням недели: `1:11:00-12:00,2:12:00-13:00,...` (1 = пн) |
| `SLOT_MINUTES` | длина слота в минутах |
| `CALL_DAYS_AHEAD` | на сколько рабочих дней вперёд открыта запись |
| `MIN_LEAD_MINUTES` | за сколько минут до слота его ещё можно выбрать сегодня |
| `COMPANY_NAME` | подставляется в текст вакансии |
| `PRIVACY_URL` | ссылка на политику обработки ПД |
| `WELCOME_IMAGE` | картинка над приветствием, по умолчанию `assets/logo.png` |
| `GOOGLE_SHEETS_URL` | адрес веб-приложения Apps Script |
| `GOOGLE_SHEETS_SECRET` | общий секрет с Apps Script |
| `ASK_RESUME` | `0` — не спрашивать резюме |
| `ASK_ABOUT` | `0` — не спрашивать «коротко о себе» |

### Куда приходят карточки кандидатов

Отправь в нужном чате (личка или группа):

```
/hr@Sales_work1_Bot
```

Бот запомнит чат в базе — правки `.env` и перезапуск не нужны. Перепривязать
можно в любой момент той же командой в другом чате. Если бота добавляют в
группу, а чат ещё ни разу не привязывали, он привяжется сам.

Пока чат не привязан, карточки печатаются в консоль — бот работает, данные в
базу пишутся.

## Google Таблица

Выгрузка идёт через Apps Script — без Google Cloud и сервисных аккаунтов.
Инструкция целиком лежит в шапке [`google-sheets/Code.gs`](google-sheets/Code.gs),
коротко:

1. Открыть таблицу → **Расширения → Apps Script**.
2. Вставить содержимое `google-sheets/Code.gs` (секрет там уже прописан).
3. **Развернуть → Новое развёртывание → Веб-приложение**, доступ «Все».
4. Скопировать выданный URL в `.env` в `GOOGLE_SHEETS_URL` и перезапустить бота.

Строка пишется при завершении анкеты и **перезаписывается** при смене статуса —
нажал «Пригласить» в Telegram, в таблице поменялось. Поиск идёт по колонке `ID`.

Если `GOOGLE_SHEETS_URL` пуст, выгрузка просто выключена. Ошибки записи в
таблицу не ломают бота: данные всегда остаются в Postgres.

## Команды

| Команда | Где | Что делает |
|---|---|---|
| `/start` | у кандидата | начать анкету; поддерживает метку источника: `?start=hh_12345` |
| `/restart` | у кандидата | заполнить анкету заново (освобождает занятый слот) |
| `/hr` | где угодно | привязать текущий чат как HR-чат |
| `/chatid` | где угодно | показать ID чата |
| `/stats` | в HR-чате | сводка по кандидатам |
| `/slots` | в HR-чате | расписание и сколько слотов свободно |
| `/export` | в HR-чате | прислать CSV со всеми кандидатами |

## Что где править

- **Текст вакансии и все сообщения кандидату** — [`src/texts.ts`](src/texts.ts).
  Код трогать не нужно. Обращение везде на «ты».
- **Логотип** — положить новый файл в `assets/logo.png`. Бот кэширует картинку
  в Telegram по `file_id`, ключ кэша завязан на размер файла, поэтому после
  замены логотипа он перезальётся сам.
- **Аватарка самого бота** — только через [@BotFather](https://t.me/BotFather):
  `/setuserpic`. Из кода это сделать нельзя, такого метода в Bot API нет.
- **Окна и длина слотов** — `.env`, логика в [`src/slots.ts`](src/slots.ts).
- **Карточка HR и кнопки** — [`src/bot.ts`](src/bot.ts), функции `hrCardText`
  и `hrKeyboard`.
- **Убрать вопрос** «о себе» или «резюме» — `ASK_ABOUT=0` / `ASK_RESUME=0`
  в `.env`. Порядок шагов перестроится сам.

## Данные

Одна таблица `candidates` плюс маленькая `settings`. Выгрузка в CSV — командой
`/export` в HR-чате или напрямую:

```bash
docker compose exec -T db psql -U postgres -d hr_bot -c "\copy (SELECT id, full_name, phone, telegram, resume_url, about, call_date, call_time, status, source, created_at FROM candidates WHERE step='done' ORDER BY call_date, call_time) TO STDOUT WITH CSV HEADER" > candidates.csv
```

## Что осознанно НЕ сделано

- **Напоминание кандидату перед созвоном.** Следующий очевидный шаг: за час до
  слота бот пишет «через час созвон».
- **Освобождение слота при отказе.** Отклонённый кандидат продолжает занимать
  своё время. При 60 слотах на две недели это заметно — стоит добавить.
- **Автоуведомление кандидата при нажатии «Пригласить».** Кнопки только меняют
  статус, писать кандидату HR должен сам.
- **Интеграция с HeadHunter.** Кандидаты приходят по ссылке, которую вы шлёте
  из кабинета HH вручную.

## Персональные данные

Бот собирает имя, телефон, Telegram и текст о себе — это персональные данные.
Перед публичным запуском нужно:

- разместить политику обработки ПД и указать её в `PRIVACY_URL`;
- подать уведомление в Роскомнадзор об обработке ПД;
- держать базу на хостинге в РФ (требование о локализации, 152-ФЗ);
- определить срок хранения и порядок удаления по запросу.

Факт согласия фиксируется: поле `consent_at` в таблице `candidates`.

## Стек

Node.js + TypeScript, [grammY](https://grammy.dev), PostgreSQL, Google Apps
Script для таблицы. Один процесс, без сборки — запуск через `tsx`.
